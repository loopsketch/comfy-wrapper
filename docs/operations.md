# 運用ガイド

入れ方と最短の使い方は [README.ja.md](../README.ja.md) にある。ここは、GPU の課金を
止めながら回すための判断と手順をまとめたもの。

## 課金の前提

Colab は生成の本数ではなく GPU の稼働時間で課金される。都度課金は 100CU = 1179円
(1CU = 11.79円)。

| GPU | CU/時 | 円/時 | VRAM | FP8 |
|---|---|---|---|---|
| L4 (既定) | 1.54 | 18.16 | 24GB | ネイティブ (sm89) |
| A100-SXM4 | 5.3 | 62.49 | 40GB | 非対応 (sm80) |

L4 を既定にしているのは、A100 の 3.44分の1 の単価に対して生成が 1.44倍しか遅くないから。
損益分岐は 3.44倍なので大きく余裕がある。根拠は [benchmarks.md](benchmarks.md)。

ここから導かれる運用が4つある。

- 確保したら必ず止める。止め忘れは寝ている間も課金が続く
- ウェイトの取得時間も課金される。まとめて投げて落とす
- 202 が返った投入は投げ直さない。届いていれば生成は走っていて、投げ直すと GPU 時間を捨てる
- 確保してから「次どうしますか」と相談している間も課金される。どこまでやるかは先に決める

## 標準の1セッション

```bash
cw status                                            # まず現状を見る
cw up --setup video --models ltx-2.5 --gpu L4 --max 60
cw video ./still.png --model ltx-2.5 --out ./clip.mp4
cw stop
```

`--setup` は `image` (静止画) / `video` (Wan2.2・LTX) / `h3` (MiniMax H3) の3つ。
`--max` は見張りの上限で、これを超えると見張りがランタイムを止める。構築(ComfyUI の
導入とウェイトの取得)には15分から25分かかる。

構築したモデルと `--model` は必ず揃える。`--models` で入れたのは1モデルだけで、
`cw image` の既定は `z-image` なので、うっかり既定のまま投げると ComfyUI が
`value_not_in_list` (400) で弾く (2026-08-12 に踏んだ)。セッションは残るので投げ直せば
済むが、往復1分から2分ぶんの GPU を掴んだままになる。

## 確保した直後に確かめる

`--gpu L4` を渡して `colab new` が成功しても、実際には CPU の VM が返ってくることがある。
2026-08-12 には、それに気づかず 28GB のウェイトを CPU 機へ落としていた。

```bash
cw sessions      # Hardware: L4 / Variant: GPU を見る
```

`cw sessions` はローカルの台帳ではなくサーバに問い合わせる。`cw status` は compose・
セッション・見張り・疎通を1画面にまとめて出す。

## 見張りの働き

`colab_watch.sh` は3つの仕事をする。keep-alive を維持し、進捗を
`.colab/keepalive-watch.log` に記録し、上限時間かアイドルでランタイムを止める。
止める前に成果物を回収する。

無進捗が続いたときの自動停止は実際に効いている。2026-08-12 に GitHub への clone が
固まった回では、ディスク使用量が 48.4GB から動かなくなった時点で8分の無進捗と判定され、
自動停止した。放置していれば上限60分まで回って18円になっていたところが3円で済んだ。

長い構築を回すときは、見張りを始めてから投げること。取得の遅さで63分かかった回に
keep-alive が落ち、成果ゼロで65円を使ったことがある。

## 止め方と確認

```bash
cw stop
```

見張り → セッション → サーバへの問い合わせ → トンネル、の順に畳む。最後にサーバの答えを
出すのは、ローカルの台帳からセッションが消えることと、リモートのランタイムが止まることが
別だから。課金は GPU 時間なので、本当に消えたかどうかは自分の目で確かめる。

最後の一覧に `[?]` で始まる名前なしのセッションが残っていたら、台帳から外れた孤児で
`cw stop -s <名前>` では引けない。`cw stop --orphans` で解放する。名前つきも含めてすべて
外したいときは `src/scripts/colab_unassign.py --all` を直接叩く。ただし一括で外すと走って
いる GPU セッションまで巻き添えになるので、まず `--dry-run` で何が消えるかを見る。

トンネルを残さないこと。セッションが無い状態でトンネルが動いていると、その
ProxyCommand (`colab ssh -s comfy`) がその名前でランタイムを確保してしまう。観測された
限りでは CPU ランタイムなので CU は減らないが、頼んでいない確保ではある。`cw stop` は
トンネルも畳む。

## 無人で1本流す

`cw run` は確保 → 構築 → 実行 → 停止 を一息で流し、失敗しても必ず止める。`--` の後ろは
`client` コンテナの Python に渡されるので、そこだけはコンテナ内のパスで書く。

```bash
cw run --setup video --models ltx-2.5 --gpu L4 --max 60 -- \
  src/scripts/measure_video.py submit works/still.png --model ltx-2.5 --aspect 9x16
```

`cw up` との違いは終わり方だけで、`cw up` はセッションを残す。

## まとめて投げる

`POST /v1/generate` は 202 を返して裏で走る。モデルのロードはセッションに1回なので、
カットを全部投入してから回収するのが基本形になる。

```bash
cw image "..." --no-wait
cw image "..." --no-wait
cw jobs              # 投入済みをまとめて回収する
```

ロードにかかるのは実測で50秒から70秒(モデルによる)。まとめ投げの利きは思ったほど
大きくなく、1本だけ回す回でも待ちが1分伸びるだけ、と読める。

## 他のプロジェクトから頼む

このリポジトリはマシンに1つだけ動かす。理由は [architecture.md](architecture.md) の
「同じマシンで2つ動かさない」にある。頼み方は2通りで、人が頼むなら `cw`、コードが
頼むなら HTTP になる。

人が頼む場合は、呼ぶ側のディレクトリでそのまま `cw` を叩く。生成物はそこに出て、
台帳とキーは comfy-wrapper 側に残る。

```bash
cd /path/to/your-project
cw image "..." --out ./assets/hero.png
```

コードから頼む場合は、共有ネットワークに乗せて `http://tunnel:8000` を解決させる。
呼ぶ側は同じ宣言を繰り返すだけでよく、ホストにポートを開けない。

```yaml
services:
  app:
    networks: [default, comfy]
networks:
  comfy:
    name: comfy-net
```

`external: true` は付けない。まだ存在しない外部ネットワークを指定すると Compose が
起動そのものに失敗し、呼ぶ側は生成と関係ない作業もできなくなる。名前を固定して
`external` を付けなければ、先に上がった方が作って後から片方が参加する。

キーはプロジェクトごとに発行して、呼ぶ側の `.env` に置く。

```bash
cw key issue --name <project>    # 平文が出るのはここだけ
cw key push                      # ハッシュをランタイムへ送る
cw key list
cw key revoke --id <id>
```

モデルの表は写さずに `GET /v1/models` から読む。写しは新しいモデルが増えた瞬間に古くなる。
実際、このリポジトリが `ltx-2.5` に対応した後も、呼ぶ側が未知のモデルとして弾いていた。
ランタイムが無いと `ready` (ウェイトが実際にあるか) だけ null になるが、カタログ自体は
ランタイム無しでも答える。見積もりは GPU を掴む前に要るので、呼ぶ側でキャッシュしておく。

呼ぶ側が知っておく必要があるのは3つだけ。投入は 202 で返って裏で走ること、ジョブ台帳は
サーバのメモリにしかないこと、ランタイムの確保と停止はこのサーバの仕事であること。
`/health` が答えなければ、いま動いていないというだけ。

実例は [music-video-creator2](https://github.com/loopsketch/music-video-creator2) にある。
このリポジトリはそこから切り出したもの。

## テスト

```bash
python3 -m unittest discover -s tests -t tests                          # ホスト
docker compose run --rm client -m unittest discover -s tests -t tests   # コンテナ
```

両方通ることを確かめる。`cw` はホストの Python で動き、`docker compose run --rm client`
はコンテナの中で動くので、リポジトリルートの解決 (`/app` かクローン先か) を間違えると
片方だけが壊れる。

GPU もランタイムもネットワークも要らない。カバーしているのは、気づかないまま GPU を
掴んでから初めて失敗するたぐいの間違いで、ワークフローのグラフ整合性、寸法とフレーム
グリッド、宛先とキーの解決、リトライの方針(POST は再送しない)、ウェイト取得前の
事前点検、止まったダウンロードの再起動、OAuth の更新、mp4 ヘッダの解釈が入っている。
