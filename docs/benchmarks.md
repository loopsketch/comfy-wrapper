# 実測記録

すべて実機で測った値。条件が違うと簡単にひっくり返るので、日付と条件を添えてある。
自分の環境で測り直すなら `src/scripts/measure_video.py` が使える。同じカットを2本続けて
生成し、1本目(ウェイトを積むところから)と2本目(積んだ状態)の差をロード時間として出す。

換算は 1$ = 157.87円、Colab は 100CU = 1179円 (1CU = 11.79円)。

## モデル間の比較 (L4、2026-08-11)

同じ静止画・同じ出力サイズ (480x854)・同じ seed・同じ平文プロンプトで揃えた 9x16 の i2v。

| model | 1本目 | 2本目 | ロード分 | 実尺 | 映像1秒あたり | 1本 | 12カット |
|---|---|---|---|---|---|---|---|
| `minimax-h3` (fp8, 20step) | 471秒 | 400秒 | 71秒 | 5.17秒 | 77.4秒 | 2.02円 | 81分 / 25円 |
| `wan2.2` (4step 蒸留) | 213秒 | 165秒 | 48秒 | 5.06秒 | 32.6秒 | 0.83円 | 34分 / 10円 |
| `ltx-2.3-gguf` (Q4_K_M) | 127秒 | 72秒 | 55秒 | 5.16秒 | 14.0秒 | 0.36円 | 15分 / 5円 |
| `wan2.2-s2v` (4step 蒸留) | 183秒 | 150秒 | 33秒 | 4.81秒 | 31.2秒 | 0.76円 | 31分 / 9円 |
| `wan2.2-s2v` (20step) | 未測定 | 1273秒 | 未測定 | 4.81秒 | 264.6秒 | 6.42円 | 255分 / 77円 |

`ltx-2.3-gguf` が頭一つ抜けている。H3 の 5.6倍、`wan2.2` の 2.3倍で、しかも音声つき 25fps。
ロードは3モデルとも50秒から70秒に収まっていて、まとめ投げの利きはそこまで大きくない。
S2V だけは step 数の差が極端で、20step は 4step の 8.5倍かかる。まず 4step で当てて、
決めカットだけ 20step にする使い分けになる。

動きの出方は速さと逆順ではない。同じプロンプト(カメラが後退しながら被写体を追い、袋が
床に散らばる)に対して、H3 は散らばる袋まで描き、LTX ははっきり後退し、wan2.2 は 4step の
ぶん一番大人しかった。H3 は本来の記法プロンプトの方が強く出るので、ここは速度を揃えて
比べるために平文で回している。

## L4 と A100 (H3、480p / 5.167秒 / 20steps、初回ロード込み)

| GPU / 量子化 | 生成時間 | 稼働コスト | 測定日 |
|---|---|---|---|
| A100 / int8 | 335秒 | 5.81円 | 2026-08-06 |
| L4 / fp8 | 483秒 (1.44倍) | 2.44円 | 2026-08-09 |

単価が 3.44分の1 で生成が 1.44倍なので、L4 の方が 2.4倍安い。A100 は FP8 を
ネイティブ実行できないので int8、L4 は Ada 世代なので fp8 を使う。21GB のモデルは L4 の
24GB に収まり、部分オフロードには落ちていない。落ちていれば 1.44倍では済まない。

## セッション単位の実測 (L4、2026-08-12)

同じ静止画を先頭フレームにして、H3 / Wan2.2 / LTX-2.3-GGUF で 480p・約5秒の i2v を作った回。
「構築」は監視の開始から ComfyUI が応答するまで。「セッション全体」は確保から停止まで。

| | 構築 | 生成 | セッション全体 | 概算 |
|---|---|---|---|---|
| 静止画 Qwen-Image 1328x1328 | 4分 | 1から2分(未計測) | 約8分 | 2.4円 |
| 動画 H3 fp8 480x480・5.17秒 | 10分 | 481秒 | 約19分 | 5.8円 |
| 動画 Wan2.2 480x480・5.06秒 | 7分 | 215秒 | 約13分 | 3.9円 |
| 動画 LTX-2.3-GGUF 480x480・5.16秒 | 6分 | 133秒 | 約9分 | 2.7円 |
| LTX-2.3 の1回目(構築失敗) | 未達 | 未達 | 約10分 | 3.0円 |

全部で約18円。生成そのものよりウェイトの取得の方が長い、という比率がはっきり出ている。
指示の追従は H3 が最も強く、書いた順番どおりに動いた。Wan はカメラ指示を無視し、LTX-2.3 は
指示を最後まで実行して被写体が画面外へ出た。

## LTX-2.5 を L4 で回す (2026-08-17)

結論として L4 で足りる。公式の int8 ウェイト(本体 21.5GB)がそのまま載り、
`loaded partially` は一度も出なかった。生成中の VRAM は 21.4/23.0GB。テキストエンコーダ
(15.4GB) は逐次ロードで入れ替わるので破綻しない。

| 条件 | 時間 | 備考 |
|---|---|---|
| 480p (512x832) / 2.04秒 / i2v | 148秒 | 1本目。ロード込み |
| 480p (512x832) / 2.04秒 / i2v | 52秒 | 2本目。ロード分は約96秒 |
| 480p (512x832) / 5.04秒 / i2v | 105秒 | 映像1秒あたり 20.8秒 = 0.53円 |
| 720p (704x1280) / 2.04秒 / i2v | 96秒 | 720p も素で回る |
| 480p (512x832) / 2.04秒 / 先頭+末尾 | 134秒 | 単パス・フル解像度なので i2v より重い |

`ltx-2.3-gguf` の 5秒 72秒には及ばない (105秒、1.46倍) が、量子化が浅く新しいデコーダが
乗ったぶんと見て釣り合う範囲。同条件で並べた回は 133秒 対 206秒で 1.55倍だった。

先頭+末尾 (flf2v) だけ構成が別で、公式テンプレートに倣い `LTXVAddGuide` を frame_idx 0 と
-1 に置いた単パス・フル解像度で回す。2段構えのアップサンプラを通さないので、同じ尺でも
i2v の 2.6倍かかった。ガイドとして積んだフレームは `LTXVCropGuides` で落としてから
デコードする。

キャラの保持は 2.3 と同じく良好で、青い首輪・毛色・黒マスクが最後まで保たれた。2.3 で
起きたフレームアウトは再現せず、代わりにカメラが正面へ寄り切って超クローズアップで
終わった。2D セル画の入力が半3D の塗りに寄って出たのは、既定ネガティブに含まれる
`cartoon, childish` が効いたため。

構築が4分34秒で終わったのは回線の当たりが良かったからで、39.9GB を瞬間 912MB/s まで
出して取り切った。2026-08-12 には 46MB/s まで落ちる回もあり、ここは運の要素が大きい。
このセッションは確保から停止まで約16分、約4.8円。

## H3 の生成時間の予測式 (A100、0.9MP / 20steps、2026-08-06)

```
生成時間 ≈ 126秒(初回ロード) + 125秒 × 尺(秒) + 63秒 × 参照枚数
```

| 条件 | 予測 | 実測 |
|---|---|---|
| ref2va 参照3枚・初回・6.583秒 | 1138 | 1138 |
| ref2va 参照2枚・初回・6.583秒 | 1075 | 1075 |
| ref2va 参照2枚・ロード済み・5.167秒 | 772 | 772 |
| fl2va 参照0枚・6.583秒 | 949 | 957 (誤差 0.8%) |

上3点はパラメータ3つに対してデータ3点なので一致は当然だが、独立した fl2va の点が誤差
0.8% で乗ったことは式の妥当性を支持する。参照画像はサンプリングの全ステップに乗るため、
枚数に線形で効く。動画1秒あたりは 720p で約145秒、生成時間は画素数にほぼ比例する。

モデルのロードには2段階あり、実測値への乗り方が違う。ディスクから CPU RAM への読み込み
(約126秒) はセッション初回だけ。CPU RAM から GPU VRAM への転送は生成中ずっと繰り返される
ので、2本目以降にも乗っている。A100 の 40GB に対して必要 VRAM が約 42.5GB あり、ComfyUI の
H3 実装がレイヤー単位に載せては解放しているため(生成中の VRAM 空きは 5GB 程度で張り付く)。
80GB クラスの GPU ならこの転送が消えるはずだが、未検証。

## 静止画モデルの比較 (A100、928x1664、同一シード、2026-08-07)

| 軸 | Z-Image Turbo | Qwen-Image 2512 |
|---|---|---|
| photoreal | 15秒。実写の質感・逆光・毛足まで良好 | 72秒(ロード込み)。室内の作り込みが一段上 |
| japanese | 15秒。4文字中 3.75文字が正確 | 6秒。同程度 |
| anime | 15秒。LoRA なしで破綻なし | 6秒。書き込み量はこちらが多い |
| character | 15秒。全身が切れず服装も再現 | 6秒。全身が入る |
| edit-pose | 手段が無い | 54秒。顔・髪型・服装を保って別ポーズ |
| edit-anime | 手段が無い | 15秒。実写シートをアニメ調へ変換 |

構成とサイズは Z-Image Turbo が 11.3GB (diffusion int8 5.78 + text enc 5.25 + vae 0.31)、
Qwen-Image 2512 が 28.0GB、Qwen-Image-Edit-2511 が +20.7GB (enc/vae は共用)。
アニメ LoRA 4本で 1.9GB。

参照画像を渡せるのは Qwen-Image-Edit だけで、その差は決定的だった。正面立ちのシート1枚から
公園のベンチに座る三分の四ビューを起こし、顔・ボブ・ミントのカーディガン・白ワイドパンツ・
クリームのスニーカー(赤ライン込み)が保たれた。

## 外部サービスとの比較

seedance (seevio) は 1000クレジット $39.9 なので 1cr = 6.299円。秒あたり 480p で 6cr、
720p で 12cr、1080p で 30cr。

| 1本 (約7秒) | seedance | Colab + H3 | 差 |
|---|---|---|---|
| 720p | 84cr = 529.1円 | 16.6円 (957秒) | 31.9倍 |
| 480p | 42cr = 264.6円 | 7.4円(推定) | 35.9倍 |

i2v を12カット(各約6.6秒)使う MV なら、seedance 6,349円 に対し Colab 199円。ただし
Colab 側は GPU を約3.2時間占有するので、安いが遅い。締め切りが迫った差し替えには
外部サービスの方が向く。

初回のモデル取得(15分から25分 = 15.6円から26.0円)は seedance 1本の20分の1以下なので、
1本生成すれば回収できる。アイドル時間も課金されるので、3時間起動して10本なら実効
18.75円/本になる。

他の GPU クラウドの相場も並べておく (2026-08時点)。

| | A100 | Colab比 |
|---|---|---|
| Colab | 40GB $0.396/時 | 1.0 |
| RunPod Secure | 80GB $1.39/時 | 3.5 |
| Lambda | 40GB $1.99/時 | 5.0 |

Colab の単価は商用 GPU クラウドの相場から見て突出して安い。移行の動機になるとすれば
価格ではなく、80GB で複数モデルを常駐できる点になる。
